# FIRE自由 Agent 文档规范

本页说明 Agent 如何把项目源资料整理为 FIRE自由 文档中心中的正式页面。

## 资料边界

- 外部项目目录只读，不得创建、修改、移动或删除其中的任何文件。
- 只有用户明确指定的外部路径可以读取；本项目当前优先使用用户指定的 `docs` 目录。
- 未获得明确授权时，不要读取项目源代码、配置、环境文件或其他目录。
- 所有生成内容只能写入当前文档工作区。
- 不执行外部项目的安装、构建、提交、推送或部署操作。

## 整理原则

1. 先阅读用户授权范围内的源文档，再开始写作。
2. 只把已经明确写出的功能、步骤、限制和风险整理进正式文档。
3. 源文档标注为草稿、待确认或需要运营复核的内容，必须保留待复核提示。
4. 内部 API 对接、待办和开发记录不自动发布为公开页面。
5. 不编造功能、参数、接口、版本号、审核策略、部署步骤或法律结论。
6. 公开页面使用简体中文；代码、命令、路径和产品原名保持原文。

## 页面要求

- 每个页面只使用一个一级标题。
- 页面开头说明文档用途和来源状态。
- 操作步骤按用户目标组织，必要时附限制和安全提醒。
- 站内链接使用相对路径。
- 图片必须提供替代文本。
- 新页面加入 `sidebars.ts` 后再运行验证。

## 推荐页面

- `index.mdx`：项目概览与文档地图。
- `getting-started.mdx`：首次使用和注册。
- `map.mdx`：生活地图和数据来源。
- `content-and-account.mdx`：内容发布与个人中心。
- `collaboration.mdx`：任务和技能协作。
- `tools.mdx`：计算器及其他工具。
- `faq.mdx`：高频问题。
- `platform-rules.mdx`：平台规则草案。
- `disclaimer.mdx`：免责声明草案。
- `agent-guide.mdx`：本页。

## 验证与交付

完成修改后运行：

```bash
npm run typecheck
npm run build
```

交付说明必须列出新增或修改的文件、内容依据、验证结果和待确认事项。不得自动提交或推送代码。
